# Game Design Document

# Project TOWER — Game Design Document

**版本：** 0.2（MVP 方案）

**引擎：** Godot 4.x / GDScript

**类型：** 2D Top-down Action Roguelite

**美术风格：** 轻像素风、剑与魔法、经典地下城幻想

**开发团队：** 3 人

**开发周期：** 14 天

**目标游玩时间：** 单局 8–12 分钟

**目标平台：** Windows PC, macOS

## 1. 游戏概述

### 1.1 核心概念

玩家扮演一名进入魔塔的冒险者，通过挥剑和释放魔法击败史莱姆、哥布林及骷髅等敌人。

清理第 1 至第 4 层后，玩家从三个随机装备奖励中选择一个，不断强化近战、魔法或者生存能力；第 5 层挑战守塔精英。

### 1.2 游戏设计支柱（Design Pillars）

**战斗爽感（Combat Satisfaction）**

- 攻击动作响应迅速。
- 怪物受击时有颜色闪烁、击退和音效反馈。
- 随着塔层推进，玩家能够明显感觉到自己变强。

**构筑成长（Build Progression）**

- 前四层各获得一次装备强化机会。
- 装备效果能够叠加。
- 不同的强化组合产生不同战斗倾向。

**短局重玩（Short Replayability）**

- 单局控制在约 10 分钟。
- 每局出现的奖励组合具有随机性。
- 死亡后可以立即重新开始。

**文本叙事与本地化（Text and Localization）**

通过地图中可阅读的遗留书页、装备短描述和层间提示，逐步呈现魔塔与过往冒险者的故事。文本是课程作业的重要组成部分，与战斗和短局节奏并重。

首发提供简体中文和美式英语，所有玩家可见文本均以可维护的双语资源管理；可选阅读不要求增加迷宫、复杂剧情或多结局。

### 1.3 不在 MVP 范围内的内容

- 开放世界或可探索迷宫
- 程序化地图生成
- 多职业角色
- 复杂装备栏与背包管理
- 商人、金币、经济系统
- 永久天赋树
- 复杂剧情、多结局
- 多人联机

## 2. 核心游戏循环

**开始游戏 → 进入塔层 → 击败敌人 → 可选阅读遗留记录 → 选择装备 → 进入下一层 → 击败守关者 → 胜利**

玩家死亡后进入失败界面，可重新开始新一局。

### 2.1 游戏状态

| **状态** | **说明** |
| --- | --- |
| MAIN\_MENU | 主菜单，开始游戏 |
| COMBAT | 正常战斗，生成并管理敌人；配置互动点的楼层清空后可安全阅读。 |
| REWARD | 暂停战斗，展示三个奖励 |
| TRANSITION | 展示下一层信息及一条玩法提示或背景短句，准备生成敌人。 |
| GAME\_OVER | 玩家死亡，显示失败界面 |
| VICTORY | 击败最终守关者，游戏通关 |

### 2.2 单局规则

- 玩家初始拥有一把剑和一个魔法技能。
- 玩家生命值在塔层之间保留。
- 第 1 至第 4 层结束后各获得一次装备三选一；第 5 层获胜后直接结算。
- 第 5 层为最终战，获胜后直接结算。
- 失败后失去本局所有强化，重新从第 1 层开始。
- 不强制实现游戏中途存档。

## 3. 战斗系统（Combat System）

### 3.1 操作方式

| **输入** | **功能** |
| --- | --- |
| WASD | 八方向移动 |
| 鼠标移动 | 控制角色面向和攻击方向 |
| 鼠标左键 | 挥剑攻击 |
| 鼠标右键 | 释放魔法弹 |
| E | 靠近可互动记录后阅读；阅读时关闭面板 |
| Enter | 安全阅读阶段跳过阅读并进入奖励选择 |
| Space | 冲刺闪避（扩展功能） |
| Esc | 关闭阅读面板；暂停菜单（扩展功能） |

默认允许持续按住攻击键重复攻击，由冷却时间控制频率。

Windows 与 macOS 使用相同的键盘、鼠标操作逻辑；macOS 的触控板辅助点按可作为右键输入。界面按当前绑定显示按键提示。

### 3.2 玩家基础属性

| **属性** | **初始值** |
| --- | --- |
| 生命值（HP） | 100 |
| 移动速度 | 185 px/s |
| 剑击伤害 | 12 |
| 剑击间隔 | 0.42 s |
| 剑击范围 | 60 px |
| 剑击角度 | 100° |
| 魔法弹伤害 | 20 |
| 魔法冷却 | 2.4 s |
| 暴击概率 | 5% |
| 暴击倍率 | 150% |
| 受伤无敌时间 | 0.6 s |

### 3.3 近战攻击

玩家朝鼠标方向挥剑，产生一个扇形攻击区域。

实现要求：

- 一次挥剑最多对同一敌人造成一次伤害。
- 扇形范围内可以同时命中多个敌人。
- 命中后敌人短暂闪白，并产生轻微击退。
- 剑击受冷却时间限制。

**实现优先级：Must Have**

### 3.4 魔法攻击

玩家朝鼠标方向发射一颗魔法弹。

实现要求：

- 魔法弹沿固定方向飞行。
- 命中敌人后造成伤害并消失。
- 碰到墙壁或超过存在时间后消失。
- 技能冷却通过 UI 显示。
- 无需魔力值（MP），仅使用冷却机制。

**实现优先级：Must Have**

### 3.5 冲刺闪避

玩家沿移动方向快速冲刺一小段距离。

初步参数：

- 冲刺时长：0.15 s
- 冷却时间：1.5 s
- 冲刺期间免疫伤害

**实现优先级：Stretch Goal**

只有在基础战斗与完整通关流程完成后才加入。

### 3.6 伤害反馈

Must Have：

- 受击闪白或闪红
- 攻击音效
- 敌人死亡动画或粒子
- 玩家生命条变化

Stretch Goal：

- 伤害数字
- 屏幕轻微震动
- 命中停顿（Hitstop）

## 4. 怪物设计（Enemy Design）

MVP 共设计三种普通敌人，以及一名复用骷髅资源的精英守关者。

### 4.1 史莱姆（Slime）

**定位：** 新手敌人 / 近距离接触伤害

| **属性** | **数值** |
| --- | --- |
| HP | 22 |
| 移动速度 | 70 px/s |
| 攻击伤害 | 8 |
| 伤害间隔 | 1.2 s |

行为逻辑：

1. 发现玩家。
2. 朝玩家位置移动。
3. 进入接触范围后造成伤害。
4. 受击后短暂闪烁。
5. HP 归零后死亡。

### 4.2 哥布林（Goblin）

**定位：** 速度较快的近战追击敌人

| **属性** | **数值** |
| --- | --- |
| HP | 38 |
| 移动速度 | 95 px/s |
| 攻击伤害 | 12 |
| 攻击前摇 | 0.5 s |

行为逻辑：

1. 主动追击玩家。
2. 进入攻击距离后停下。
3. 播放短暂攻击前摇。
4. 朝玩家方向发动近战攻击。
5. 攻击结束后重新追击。

哥布林的核心特色是攻击具有预警，允许玩家通过移动躲避。

### 4.3 骷髅法师（Skeleton Mage）

**定位：** 远程攻击敌人

| **属性** | **数值** |
| --- | --- |
| HP | 30 |
| 移动速度 | 55 px/s |
| 魔法弹伤害 | 10 |
| 攻击间隔 | 2.6 s |

行为逻辑：

1. 与玩家保持一定距离。
2. 在攻击范围内定期发射魔法弹。
3. 玩家距离过近时尝试后退。
4. 被近战攻击命中时承受击退。

骷髅法师迫使玩家改变走位，而不是只需要不断挥剑。

### 4.4 守塔精英（Elite Skeleton）

**定位：** 最终精英敌人

| **属性** | **数值** |
| --- | --- |
| HP | 160 |
| 移动速度 | 55 px/s |
| 魔法弹伤害 | 12 |
| 攻击间隔 | 2.8 s |

行为：

- 复用骷髅法师的基本 AI。
- 体型更大，颜色明显不同。
- 每次攻击发射三颗扇形散射魔法弹。
- 生命值较低时可适度加快攻击频率（扩展功能）。

**不制作独立复杂 Boss 行为树。**

## 5. 装备与 Build 系统

### 5.1 装备规则

MVP 采用简化的被动装备机制：

- 第 1 至第 4 层结束后各随机展示 3 件装备。
- 玩家必须选择其中 1 件。
- 获得装备后立即生效。
- 不存在装备栏上限。
- 装备无法主动卸下或出售。
- 同一奖励界面不得出现重复选项。
- 不同塔层可以再次出现相同装备，效果允许叠加。

这意味着玩家无需管理背包，但仍能体验构筑成长。

### 5.2 初始装备列表

| **ID** | **装备** | **效果** |
| --- | --- | --- |
| U01 | 锋利长剑 | 剑击伤害 +6 |
| U02 | 疾风手套 | 剑击冷却 ×0.8 |
| U03 | 烈焰法杖 | 魔法弹伤害 +12 |
| U04 | 奥术戒指 | 魔法冷却 ×0.75 |
| U05 | 幸运徽章 | 暴击率 +15 个百分点 |
| U06 | 吸血剑刃 | 使用剑击击杀敌人恢复 5 HP |
| U07 | 骑士铠甲 | 最大 HP +25，同时恢复 25 HP |
| U08 | 迅捷长靴 | 移动速度 +15% |

数值限制：

- 剑击冷却不低于 0.22 s。
- 魔法冷却不低于 1.0 s。
- 暴击率不超过 60%。
- 恢复生命不得超过当前最大 HP。

### 5.3 Build 方向

**近战流**

核心装备：锋利长剑、疾风手套、吸血剑刃。

特点：持续输出、击杀恢复生命、适合贴近敌人战斗。

**魔法流**

核心装备：烈焰法杖、奥术戒指。

特点：提高魔法爆发及释放频率，适合远程消耗。

**均衡生存流**

核心装备：骑士铠甲、迅捷长靴、幸运徽章。

特点：提高生存容错，利用移动与暴击完成战斗。

这些只是构筑倾向，并非互斥职业。

### 5.4 装备效果计算

装备改变玩家运行时属性，而不是直接修改攻击脚本中写死的数值。

示例：

- 基础剑击伤害 = 12。
- 获得两次锋利长剑 = 12 + 6 + 6 = 24。
- 基础剑击冷却 = 0.42 s。
- 获得一次疾风手套 = 0.42 × 0.8 = 0.336 s。

装备系统必须支持重复强化。

### 5.5 装备叙事短描述

每件装备在奖励卡中展示本地化名称、独立的明确效果说明和一条简短叙事描述。叙事文字补充气氛，不替代数值；效果数值来自实际装备数据。以下为初始双语文案。

**U01 锋利长剑 / Sharpened Longsword**

中文：剑刃上的细小缺口，是每一次挥砍留下的记号。  
English: Tiny nicks along the blade mark every swing.

**U02 疾风手套 / Swiftwind Gloves**

中文：轻薄的手套让持剑的手如风般敏捷。  
English: These light gloves let a sword hand move as swiftly as the wind.

**U03 烈焰法杖 / Flame Staff**

中文：杖尖残留的温度，像一团不肯熄灭的余烬。  
English: Warmth lingers at the tip, like an ember that refuses to die.

**U04 奥术戒指 / Arcane Ring**

中文：戒面刻着一圈细密符文，微光随呼吸起伏。  
English: Fine runes circle the ring, their glow rising and falling with each breath.

**U05 幸运徽章 / Lucky Emblem**

中文：磨损的徽章被无数次攥紧，仿佛能为旅人留住好运。  
English: Worn smooth by countless anxious grips, this emblem seems to hold a traveler’s luck.

**U06 吸血剑刃 / Lifedrinker Blade**

中文：暗红的纹路沿刃脊延伸，仿佛仍在脉动。  
English: Dark red lines run along the blade, as if they still pulse.

**U07 骑士铠甲 / Knight’s Armor**

中文：铠甲上布满修补痕迹，却依旧可靠。  
English: Repairs cover this armor, but it remains dependable.

**U08 迅捷长靴 / Swift Boots**

中文：鞋底的磨痕，记录着一位旅人走过的漫长道路。  
English: The worn soles tell of the long road a traveler once walked.

## 6. 塔层与关卡系统

### 6.1 基础规则

采用单张固定尺寸战斗场景，重复使用五次。

每层通过以下参数产生变化：

- 怪物种类
- 怪物数量
- 怪物出现批次
- 背景颜色或装饰
- 战斗难度

**不进行真正的随机地图生成。**

### 6.2 塔层配置

| **层数** | **敌人配置** | **设计目的** |
| --- | --- | --- |
| F1 | 史莱姆 2 只；第二波史莱姆 1 只 + 哥布林 1 只 | 学习移动和攻击 |
| F2 | 两波史莱姆与哥布林混合敌人 | 练习走位，感受第一次强化 |
| F3 | 两波哥布林与骷髅法师组合 | 引入远程攻击压力 |
| F4 | 两波三种普通敌人混合配置 | 检验 Build 与战斗技巧 |
| F5 | 守塔精英 1 只 + 少量普通敌人 | 最终挑战 |

战斗空间应确保玩家有足够的移动余地。

怪物必须在玩家一定距离之外出现，且出生时不可立即造成伤害。

### 6.3 塔层状态

每层分为：

1. ENTER：展示塔层名称。
2. SPAWN：生成当前批次敌人。
3. FIGHT：进入战斗。
4. CHECK：检测是否清空所有批次；有记录时进入可跳过的安全阅读阶段。
5. REWARD：前三个塔层及第四层展示奖励。
6. NEXT：进入下一层，或第 5 层胜利结算。

前三个塔层和第四层各获得一次装备奖励，因此一局最多获得四次强化。

### 6.4 时间控制

期望将战斗、可选阅读、奖励选择和层间过渡控制在总计 8–12 分钟。

不设置强制倒计时。

通过怪物数量、敌人 HP 和战斗波次调节实际游戏长度，优先依据真实试玩数据调整。

### 6.5 地图互动与叙事文本

MVP 在复用的固定战斗场景中配置两个可阅读互动点：第 1 层的古旧书页介绍魔塔历史，第 3 层的冒险者手记记录前人的经历。按楼层启用对应装饰和文本，不新增地图生成或探索迷宫。

仅在该层全部批次敌人被击败后开启安全阅读阶段；此时不再生成敌人。界面显示 Enter 进入奖励的提示，靠近记录时显示 E 阅读提示。玩家按 E 打开，按 E 或 Esc 关闭，或在面板关闭时按 Enter 直接进入三选一奖励。阅读完全可选，同一阶段可重复阅读。

无互动点的第 2、4 层清场后直接进入奖励；第 5 层击败精英后仍直接胜利。阅读面板打开时屏蔽角色移动、攻击和进入奖励的输入；关闭后恢复安全阶段输入。

FloorManager 在清空全部批次后只发送一次 floor\_cleared，RunController 决定是否先进入安全阶段，再打开 REWARD；避免重复奖励或误启动下一波。互动点不提供战斗数值或强制收集奖励。

**F1 古旧书页 / A Fragment of History**

中文：古塔建成时，守塔人点亮了一盏灯。许多年后，灯仍亮着，却再无人记得最初是谁将它点燃。  
English: When the old tower was built, its keepers lit a lamp. Years later, it still burns, though no one remembers who first lit it.

**F3 冒险者手记 / An Adventurer’s Note**

中文：第三层的回声比我快一步。我在墙边歇了一会儿，才明白独自前行，并不意味着没有人曾走过这条路。  
English: On the third floor, my echo ran ahead of me. I rested by the wall and realized that walking alone doesn’t mean no one has walked this way before.

## 7. UI / UX 设计

### 7.1 主菜单

- 游戏标题
- Start Game
- Quit Game
- 简短操作说明

- 语言选择：简体中文 / English (US)，在主菜单立即生效并保存。

### 7.2 战斗 HUD

屏幕左上：

- 当前 HP / 最大 HP
- 简易生命条

屏幕右上：

- 当前塔层（Floor 1/5）
- 当前剩余敌人数量

屏幕下方：

- 魔法技能冷却图标
- 当前获得的装备图标（可简化为文本）

### 7.3 装备选择界面

显示三个并排的装备卡片。

每张卡片包含：

- 装备名称
- 图标
- 效果说明

- 叙事短描述：独立于效果说明，参考 5.5。

玩家点击卡片后立即获得强化，并进入下一层。

奖励选择期间暂停敌人行动。

### 7.4 结算界面

胜利 / 失败页面显示：

- 本局到达层数
- 击败敌人数量
- 游戏用时
- 获得的装备
- Restart 按钮

### 7.5 语言选择

主菜单提供简体中文（zh-CN）与美式英语（en-US）。玩家切换后当前菜单立即刷新，选择写入本地设置，下次启动时保留。首次启动优先匹配系统语言；不支持或无法识别时默认简体中文。暂停菜单仍为扩展功能，不作为语言切换前提。

菜单、HUD、操作提示、奖励卡、记录、过场和结算界面的所有玩家可见文字均随选择显示；数字、变量、字体、自动换行与可阅读空间在两种语言下检查。

### 7.6 层间过渡文本

TRANSITION 在下一层信息旁显示一条玩法提示或一句世界背景，从已翻译的短文本池中选取；内容应与当前规则及世界设定一致。避免过短闪现或强制长等待，时长随原有过渡节奏和试玩调整。

**玩法提示示例**

中文：剑击和魔法弹都朝鼠标所指的方向发出。  
English: Your sword and magic projectiles aim toward the mouse cursor.

中文：第 1 至第 4 层结束后，从三件装备中选择一件。  
English: After floors 1 through 4, choose one of three upgrades.

**世界背景示例**

中文：塔中的遗物，仍保留着曾经到访者的痕迹。  
English: Relics in the tower still bear traces of those who came before.

## 8. Godot 技术架构

### 8.1 核心原则

采用**场景组合 + 事件信号 + 数据驱动配置**。

不使用复杂 ECS 框架，不在 MVP 阶段构建独立插件系统。

### 8.2 主要场景

```
Main.tscn
├── RunController
├── Arena
│   ├── TileMapLayer
│   └── Walls
├── Actors
│   ├── Player
│   └── Enemies
├── Projectiles
├── SpawnPoints
└── UI
    ├── HUD
    ├── RewardPanel
    └── ResultPanel
```

角色与敌人独立制作：

```
Player.tscn
EnemySlime.tscn
EnemyGoblin.tscn
EnemySkeleton.tscn
EliteSkeleton.tscn
MagicProjectile.tscn
```

所有怪物复用公共伤害处理和血量逻辑。

Arena 可按楼层启用 LoreObject；UI 增加可复用的 LorePanel 和语言选择控件。它们接收文本 ID，通过统一翻译资源显示内容，不把具体语言硬编码进场景逻辑。

### 8.3 推荐目录结构

```
res://
├── scenes/
│   ├── main.tscn
│   ├── player/
│   ├── enemies/
│   ├── combat/
│   └── ui/
├── scripts/
│   ├── player.gd
│   ├── enemy_base.gd
│   ├── run_controller.gd
│   ├── floor_manager.gd
│   └── reward_manager.gd
├── data/
│   ├── enemies/
│   ├── upgrades/
│   └── floors/
├── assets/
│   ├── sprites/
│   ├── audio/
│   └── fonts/
└── docs/
    └── GDD.md
```

补充目录：res://localization/ 保存导入用的双语文本 CSV；res://data/lore/ 保存互动点数据；docs/localization/ 保存上下文、术语与审校记录。

### 8.4 主要模块

**PlayerController**

负责：

- 玩家移动
- 攻击输入
- 基础属性
- 生命值管理
- 受击与死亡

**CombatSystem**

负责：

- 命中检测
- 伤害计算
- 暴击计算
- 攻击冷却
- 简单击退

**EnemyBase**

负责：

- HP / 伤害处理
- 受击反馈
- 死亡事件

具体敌人行为由各自脚本控制，避免一个脚本承担所有 AI 类型。

**FloorManager**

负责：

- 当前层数
- 敌人批次与生成位置
- 检测层内敌人是否全部死亡
- 发出楼层完成事件

**RewardManager**

负责：

- 随机抽取三个不同装备
- 处理玩家选择
- 应用强化效果

**RunController**

负责：

- 游戏状态转换
- 新一局初始化
- 胜利 / 失败结算
- 统计游戏时长与击杀数量

LocalizationService：加载并切换语言、保存设置、向界面提供翻译；LoreObject / LorePanel：在安全阶段显示互动提示并读取对应文本 ID。RunController 协调阅读阶段和奖励界面。

### 8.5 模块交互约定

核心接口：

```
Player:
  take_damage(amount)
  heal(amount)
  apply_upgrade(upgrade)
 
Enemy:
  take_damage(amount)
  signal died(enemy)
 
FloorManager:
  start_floor(floor_index)
  signal floor_cleared
 
RewardManager:
  generate_choices(count)
  signal upgrade_selected(upgrade)
 
RunController:
  start_run()
  next_floor()
  end_run(is_victory)
```

开发前需统一这些接口命名及参数。

### 8.6 数据设计

建议使用 Godot 的自定义 Resource 配置敌人和强化属性，避免把所有数据直接写进代码逻辑。

EnemyData：

```
id
name_key
max_hp
move_speed
damage
attack_cooldown
```

UpgradeData：

```
id
name_key
effect_text_key
flavor_text_key
icon
effect_type
effect_value
```

FloorData：

```
floor_number
enemy_waves
environment_theme
lore_ids
```

装备属性与实际运行中的玩家属性应当分开保存。

LoreData：id、floor\_number、title\_key、body\_key 和位置；文本 key 引用双语资源。装备效果文本中的占位符使用 effect\_value 等实际数据填充，数值计算不依赖显示语言。

### 8.7 碰撞设计

建议使用 Godot 物理碰撞层区分：

1. World：墙壁 / 环境
2. Player：玩家
3. Enemy：敌人
4. PlayerAttack：玩家攻击区域
5. EnemyAttack：敌人攻击区域

攻击区域只检测相应目标，不检测友方单位。

### 8.8 工程协作

- 统一 Godot 4.x 的同一个具体版本。
- 使用 Git 仓库管理项目。
- 启用 Godot 文本场景格式。
- 不允许多人同时修改同一核心场景。
- 开发使用独立 Feature Branch，合并前运行测试。
- 每天至少产生一次可运行版本。
- 游戏入口场景必须始终保持可运行。

### 8.9 多语言文本系统与管理

**语言和显示**

对玩家使用 zh-CN、en-US 语言标识；在 Godot 资源中采用对应 locale：zh\_CN、en\_US。调用 TranslationServer 设置语言，语言变化时刷新当前界面和动态生成文本。将用户选择保存在 user:// 下的设置文件中。

首次启动映射受支持的系统语言，匹配不到则使用 zh-CN；之后优先使用用户保存的选择。暂停菜单不在 MVP 范围内，因此语言入口设在主菜单。

**数据与资源**

统一使用 UTF-8 CSV 作为翻译源，列为 keys、zh\_CN、en\_US；导入 Godot 翻译资源并确认已纳入项目和双平台导出包。每条面向玩家的文案使用稳定、唯一的 ID，游戏逻辑只引用 ID。

示例 ID：UI\_MENU\_START、ITEM\_U01\_NAME、ITEM\_U01\_EFFECT、ITEM\_U01\_LORE、LORE\_F1\_TITLE、LORE\_F1\_BODY、TRANSITION\_TIP\_01。装备名称、明确效果和叙事描述分别管理；楼层和物品数据保存对应 ID。

在 docs/localization/ 为每个 ID 记录出现界面、说话者或对象、字符空间、变量含义、翻译状态和审校备注；维护统一术语表。CSV 只保存 Godot 导入所需列，避免把上下文误识别为语言。

**更新与回退**

新增或修改文案时同时更新两种语言、上下文和术语；代码评审检查重复 ID、缺失译文、失效引用、占位符不一致及误写进代码的玩家文本。数值、标点、百分比和换行在两种语言中核对。

未找到当前语言条目时回退到 zh-CN 并记录缺失 ID；若默认条目也缺失，显示可理解的兜底提示并记录错误，不把原始 ID 作为正常文案。最终交付前清零缺失项。

使用覆盖中文和英文的授权字体及回退字体，确保界面可换行或完整阅读；英文较长文本不应遮挡按钮、数值或交互提示。

实现参考：Godot 4 官方文档 Importing translations 与 Internationalizing games；项目实际使用的 Godot 4.x 版本应与导入、字体及语言切换方案一并验证。

## 11. 测试验收标准

### 11.1 功能验收

- 玩家可正常移动和攻击。
- 所有怪物可以生成、攻击、受伤和死亡。
- 魔法弹不会错误攻击玩家自己。
- 伤害不会因单次碰撞重复异常触发。
- 角色 HP 归零后进入失败页面。
- 五层战斗可以连续完成。
- 每次奖励展示三个不同的装备选项。
- 所有装备效果正确应用。
- 精英敌人死亡后触发胜利。
- Restart 可以完全重置游戏状态。
- 导出后的程序可以独立运行。

- Windows 和 macOS 导出版本均可启动并完成移动、攻击、互动、奖励、胜利和失败流程。
- 可在主菜单切换简体中文 / 美式英语，当前界面更新；重启后语言选择保留。
- 第 1、3 层清场后能打开、完整阅读并关闭记录，也能跳过阅读直接获得奖励；无互动点楼层及最终胜利流程正常。
- 所有已实现装备具有中英文名称、效果说明和叙事短描述；数值与实际效果一致，TRANSITION 可显示双语短文本。
- 两种语言的翻译资源均包含在两个导出包中；检查缺项回退、占位符、字体缺字、溢出及长文本换行。

### 11.2 体验验收

- 新玩家可以在约 30 秒内理解基本操作。
- 玩家能够明显分辨三种普通敌人的攻击方式。
- 近战与魔法两种攻击都具有实际价值。
- 选择不同装备后能够感受到强度变化。
- 试玩者典型通关时长接近 8–12 分钟。
- 死亡与受击原因可以被玩家理解。
- 5 层战斗具有逐渐增加的挑战性。

- 可选记录不阻碍战斗、领奖和通关，且两种语言中的叙事、术语与操作含义一致。

## 12. 风险与降级预案

| **风险** | **降级措施** |
| --- | --- |
| 战斗开发延误 | 删除冲刺和高级特效 |
| 精英 AI 实现困难 | 使用强化版骷髅法师 |
| 装备系统复杂 | 保留 6 个纯属性强化，并为保留装备提供双语名称、效果和短描述 |
| 像素美术制作延误 | 使用统一风格的授权素材 |
| 游戏时长不符合目标 | 根据试玩调整波次和敌人数量 |
| 场景制作工作量过大 | 只使用一张战斗地图 |
| UI 来不及实现 | 采用纯文字装备卡片与阅读面板，保留效果、叙事描述和双语切换 |
| 音效资源不足 | 优先保证命中、受伤、死亡三类音效 |

本地化或平台测试时间不足时，优先保留两种语言的完整关键流程、两个短互动点及 Windows / macOS 导出；削减额外文案数量或视觉装饰，不删除语言切换与关键操作说明。

### 12.1 强制范围冻结

- Day 3 后不再增加新的核心战斗机制。
- Day 7 后不再增加新的游戏系统。
- Day 10 后原则上不再增加新玩法，仅修复与调整。
- Day 12 后以稳定交付为最高优先级。
