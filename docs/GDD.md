## 1 游戏定位与交付范围

Project TOWER 是一款单人 2D 俯视角动作 Roguelite。玩家带着剑和魔法进入古塔，在五层竞技场中边走位边战斗，在第 1 至第 4 层清场后选择一项强化来形成当局构筑，最终挑战守塔精英。书页、手记与遗物短文讲述前人留下的痕迹，玩家可以自行决定阅读多少。

以 Godot 4.7.2 和 GDScript 开发，支持 Windows x86_64、macOS 通用架构、简体中文和美式英语。采用键鼠操作和轻像素地下城风格，面向首次接触游戏的玩家。目标是约 30 秒理解基本操作，典型通关 8–12 分钟。这两项是试玩目标。

v0.3 的交付范围覆盖五层战斗、三类普通敌人与一名精英、八件装备、四次奖励、两处可选阅读、双语界面和胜负结算。打磨集中在敌我辨识、攻击反馈、精英预警、音效、奖励预览和五层节奏。冲刺、暂停菜单、新敌人、新地图、局外成长和装备稀有度属于后续扩展。

## 2 单局流程与操作

<a name="game-states"></a>

### 2.1 游戏状态

| 状态 | 玩家体验与流转 |
| --- | --- |
| 主菜单 MENU | 选择语言、查看键鼠说明，开始游戏或退出。 |
| 层间过渡 TRANSITION | 展示即将进入的楼层和一条双语短提示。进入首层和领取奖励后均播放，基线时长 2.1 秒。 |
| 战斗 COMBAT | 走位、攻击并应对分批出现的敌人。F1 至 F4 在全部波次清空后进入对应结算流程。 |
| 安全阅读 SAFE | F1、F3 清场后停止刷怪并清空弹体。玩家可走近记录阅读，也可直接进入奖励。 |
| 奖励 REWARD | F1 至 F4 各出现一次三选一。暂停战斗输入，点击卡片后当即应用强化，进入下一层。 |
| 胜利或失败 | F5 精英死亡进入 VICTORY 并清理敌人与弹体。HP 归零进入 GAME_OVER。胜负页均可重开或回到主菜单。 |

每局从 F1 和初始属性开始，生命和强化在相邻楼层间保留。结算用时包含层间过渡、战斗、阅读及奖励选择。重新开始时清理旧敌人、弹体、奖励与统计，语言偏好继续生效。

<a name="controls"></a>

### 2.2 键鼠操作

| 输入 | 行为 |
| --- | --- |
| WASD | 八方向移动。斜向输入归一化，移动范围受竞技场边界限制。 |
| 鼠标移动 | 瞄准并决定挥剑与魔法射向。 |
| 鼠标左键和右键 | 左键挥剑，右键发射魔法弹。可长按，达到相应冷却后再次攻击。 |
| E 和 Esc | 安全阶段靠近记录后按 E 阅读，面板打开时按 E 或 Esc 关闭。 |
| Enter | 安全阶段、阅读面板关闭时，跳过或结束阅读并进入奖励选择。 |

<a name="combat-and-enemies"></a>

## 3 战斗与敌人

玩家以剑击清理近处敌人，用魔法弹远程输出。三类普通敌人分别施加接触、近战和弹道压力，守塔精英以有预警的散射收束战斗。

见[《战斗与敌人》](design/v0.3/combat-and-enemies.md)文档。

<a name="floors-and-narrative"></a>

## 4 五层关卡与叙事

五层复用同一竞技场。普通关卡按波次推进，F1 和 F3 清场后可阅读记录，F5 击败守塔精英即结算胜利。

见[《五层关卡与叙事》](design/v0.3/floors-and-narrative.md)文档。

<a name="equipment-and-reward-preview"></a>

## 5 装备与奖励预览

F1 至 F4 清场后各从三件随机装备中选择一件，强化可跨层叠加。奖励卡预览选中后实际生效的属性和限制。

见[《装备与奖励预览》](design/v0.3/equipment-and-reward-preview.md)文档。

<a name="ui-and-localization"></a>

## 6 界面与本地化

菜单、战斗 HUD、阅读、奖励和结算提供简体中文及美式英语。主菜单即时切换并保存语言，遗物短句和层间提示随界面本地化。

见[《界面与本地化》](design/v0.3/ui-and-localization.md)文档。

<a name="team-and-schedule"></a>

## 9 三人分工与排期

<a name="roles"></a>

### 9.1 成员职责

| 成员 | 主责 | 交付与协作 |
| --- | --- | --- |
| PM | 项目管理、美术和音频素材制作 | 维护范围、排期和交付清单，确定风格与资源优先级，制作与整理美术、音效样件及成品，留存来源许可。接收 QA 的验收结果，协调修复优先级、冻结范围和最终提交。 |
| Engineer | 模块化程序更新与迭代 | 负责战斗、关卡、装备、UI、本地化及游戏内美术与音效接入。维护模块接口和数据，运行自动化回归，修复缺陷并导出双平台候选包。 |
| QA | QA 和演示录制 | 准备测试设备、用例及外部试玩，完成双平台、双语和可用性验证，登记并复测问题。准备脚本和镜头清单，录制、剪辑并核对演示成片。 |

PM 将素材交给 Engineer 接入，Engineer 回传可玩包供 QA 验证。QA 将缺陷和复现条件反馈给 Engineer，同时向 PM 报告会影响范围或交付的事项。PM 根据样板评审与验收记录决定是否降级。

<a name="milestones"></a>

### 9.2 计划与验收节点

实施计划为 2026 年 11 月 17 日至 30 日。任务起止与前置编号见同期 v0.3 甘特图，同日工作按交接顺序进行。

| 日期 | 节点 | 交付与交接 |
| --- | --- | --- |
| 11 月 17–18 日 | 范围与基线 | PM 确认规格和验收口径。Engineer 出双平台基线包并准备接入。PM 协调设备与试玩需求。 |
| 11 月 19–22 日 | F1 样板与 M1 | PM 完成美术与短音效样件。Engineer 先准备战斗事件和动效，再完成 F1 接入。QA 确认设备与试玩安排，预检两端基线并试玩样板，PM 在 22 日确认扩展范围。 |
| 11 月 23–25 日 | 五层整合与 M2 | PM 于 24 日交付五层所需素材及来源。Engineer 迭代奖励预览与楼层节奏，再接入成品、F5 预警与混音。QA 检查完整流程，PM 于 25 日冻结玩法范围。 |
| 11 月 25–27 日 | 试玩和修复 | QA 组织计时试玩与双语走查。Engineer 修复并跑回归。QA 准备脚本、试录并于 27 日复验阻塞问题。PM 汇总说明、总结和授权。 |
| 11 月 28–29 日 | 候选包及 M3 | Engineer 导出双平台候选包。QA 进行实机验收，候选包基本回归通过后录制。PM 于 29 日核对候选包、成片与验收记录。 |
| 11 月 30 日 | 最终交付 M4 | PM 检查归档、包版本、成片播放与材料齐备情况并提交。 |

11 月 25 日冻结后，优先修正交付阻塞问题及有试玩依据的数值问题。候选包有改动时，Engineer 更新版本，QA 按影响范围复验并核对镜头。PM 据此确认提交包。

## 10 测试验收与降级

<a name="acceptance"></a>

### 10.1 基线与 v0.3 验收

仓库 [`docs/QA.md`](QA.md) 记录 v0.2 基线的 440 项无头检查、两端包导出及 macOS 独立包主菜单启动。五层流程由测试事件推进。v0.3 需补齐两端目标设备的完整流程、真人计时通关、双语审校及游戏内听感。

| 验收项 | 需验证的行为与记录 |
| --- | --- |
| 自动化回归 | Engineer 运行 Godot 4.7.2 无头导入及 [`tests/test_mvp.gd`](../tests/test_mvp.gd)。重点验证伤害、清场信号、奖励只应用一次、叠加与上下限、预览和实际属性一致、F5 预警先于出弹、胜负与重置。 |
| 双平台与输入 | QA 用 Windows x86_64 与 macOS 独立候选包验证启动、移动、瞄准、剑击与魔法、阅读及跳过、领奖、通关、死亡及重开。另查 macOS 触控板辅点。记录设备、操作系统、构建号与 macOS 签名、公证和启动结果。 |
| 双语与 UI | 两种语言验证即时切换和重启保存，核对主菜单、HUD、八件装备、阅读、过渡与结算。检查术语、变量、字体、缺项回退、换行、溢出与按钮。最终包中双语条目齐备。 |
| 战斗反馈与声音 | 核对挥空、命中、敌我施法、受伤、死亡与领奖。观察敌我外观、弹道和 F5 方向预警，密集战斗中检查视效可读性及叠音。听取独立包的实际输出。 |
| 真人试玩 | 请未参与开发的玩家读操作并从 F1 开始。记录选装理解、敌人辨识、各层与整局时间、胜负和卡点。观察能否约 30 秒掌握基本操作，通关样本是否接近 8–12 分钟。 |

QA 记录构建号、设备、语言、复现步骤、预期和实际结果，严重缺陷附截图或日志。复验后保留试玩样本数和调整原因，PM 核对阻塞项状态。

<a name="contingencies"></a>

### 10.2 延期时的取舍

| 情况 | 处理方式 |
| --- | --- |
| F1 美术或动效样板未达标 | 先保留敌我剪影、楼层辨识和危险预警，缩减逐层装饰及次要粒子，使用成熟的程序绘制作为替补。 |
| 生成音效难辨、失真或许可待确认 | 使用现有程序合成或调音后的关键提示。优先保证挥空、命中、受伤、死亡、领奖和威胁提示，环境氛围按时间取舍。 |
| 预览或英文卡面过拥挤 | 缩减卡面装饰，保留可读的文本预览、数值限制与叙事短句，检查两种语言的换行。 |
| 通关时长或难度偏离目标 | 根据试玩记录调整波次、血量、生成间隔和预警时长，保留五层和四次奖励。 |
| 平台或录制进度紧张 | 及早做设备与独立包预检。优先解决启动、输入、五层推进和双语流程，演示先保留可读战斗、选装和精英镜头。 |

<a name="demo-recording"></a>

### 11.2 演示录制与核对

QA 先完成镜头清单和试录。候选包通过基本回归后，录制实机战斗、一次选装和奖励预览，以及楼层变化或精英预警。剪辑后检查画面、文字和提示音，调整旁白和配乐音量。

QA 记录录制用的构建号，版本变更影响展示内容时核对并补录。PM 核对视频可播放、所示内容与提交包一致、两端游戏包通过验收。
